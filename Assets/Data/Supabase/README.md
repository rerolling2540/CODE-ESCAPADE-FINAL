# Card Data Editor

Open `Assets/Scenes/Card Data Editor.unity` and enter Play mode. The scene builds its editor UI at runtime.

## Supabase setup

1. Run `cards_schema.sql` in the Supabase SQL Editor.
2. In the scene, enter your Supabase project URL, anon/publishable key, and an authenticated user's access token (JWT), then choose **Connect**.
3. The editor uses the Supabase REST Data API on the `public.cards` table. It can list, create, update, and delete records.
4. `image_url` is a URL reference, such as a public Supabase Storage URL. Upload the image to Storage separately and paste its public URL into the editor.

The service-role key must never be placed in the Unity client. The SQL policy allows authenticated users to manage the table; use a user's access token so row-level security remains enabled. Connection values are kept in memory only and are not saved to PlayerPrefs or project files.

## Cross-device player saves

Run `player_saves_schema.sql` in the same Supabase project's SQL Editor. The Unity login flow automatically uploads guest save slots and inventory to the signed-in user's row, or downloads the account save when the device has no local progress. If both sides have progress, it merges slot by slot and keeps the newer version of each slot with its matching inventory. Changes to save slots and inventory sync while the session is active. Row-level security restricts each user to their own save.

## Card columns

`id` is a UUID generated by Supabase. The editor reads and writes `name`, `description`, `mana`, `image_url`, `damage_type` (`0` flat, `1` percent of attack), `base_damage`, `percent_damage`, and `damage_multiplier`.
